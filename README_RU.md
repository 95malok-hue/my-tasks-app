# Приложение «Мои задачи» — стартовый проект

Проект содержит WEB/PWA-версию и заготовку сборки Android APK через GitHub Actions. Обе версии используют одну базу Supabase.

## Важно перед запуском

1. Создай проект в Supabase.
2. Открой SQL Editor, вставь весь файл `supabase.sql` и нажми Run.
3. В Supabase открой Project Settings → API. Скопируй Project URL и publishable/anon key.
4. Открой `www/config.js` и замени два значения-заглушки на свои URL и ключ.
5. В Supabase → Authentication → URL Configuration добавь адрес WEB-сайта в Site URL и Redirect URLs после публикации.
6. В Authentication → Providers → Email настрой подтверждение почты по желанию. Для первого теста можно отключить Confirm email, но для постоянного использования лучше оставить подтверждение включённым.

## Публикация с Android-телефона

1. Создай аккаунт GitHub и новый пустой репозиторий, например `my-tasks-app`.
2. Распакуй архив на телефоне. Загрузи содержимое папки проекта в репозиторий, сохраняя структуру (`www`, `.github`, `package.json` и т.д.). В GitHub можно загружать файлы через браузер; для папок удобнее GitHub Mobile или веб-редактор репозитория.
3. После загрузки открой Settings → Pages и выбери публикацию через GitHub Actions.
4. Открой вкладку Actions и запусти `Deploy WEB app`. Адрес сайта появится в успешном запуске.
5. Добавь адрес сайта в Supabase Authentication → URL Configuration.
6. Для APK открой Actions → `Build Android APK` → Run workflow. После успешной сборки открой запуск workflow, раздел Artifacts и скачай `my-tasks-debug-apk`. Внутри будет `app-debug.apk`.
7. Разреши установку APK из браузера/файлового менеджера Android и установи приложение.

## Как работает удаление через 48 часов

Когда задача отмечена выполненной, сервер записывает `completed_at`. Задача остаётся в списке выполненных, а Supabase Cron проверяет таблицу раз в минуту и удаляет записи, у которых прошло 48 часов. Удаление не зависит от того, открыто ли приложение.

## Что уже реализовано

- регистрация и вход по email/паролю;
- создание задачи с названием и описанием;
- просмотр описания нажатием на карточку;
- отметка выполнения;
- отдельный список выполненных задач с таймером до удаления;
- синхронизация изменений через общую базу и realtime;
- светлая адаптивная WEB/PWA-версия;
- автоматическая сборка APK через GitHub Actions.

## Безопасность

В приложении используется только Supabase publishable/anon key. Никогда не вставляй `service_role` key в `config.js` или клиентский код. Политики RLS ограничивают доступ задачами текущего пользователя.

## Ограничения стартовой версии

Это первый рабочий каркас, а не уже опубликованный сервис: нужны настройки Supabase и GitHub. После настройки проверь вход, создание задачи, синхронизацию на двух клиентах и серверное удаление. Для production APK лучше отдельно настроить подписанный релизный APK; workflow сейчас создаёт debug APK для установки и тестирования.
